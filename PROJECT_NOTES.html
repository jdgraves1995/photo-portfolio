1. Project Goal

A personal photography portfolio where the owner can upload RAW images and share URLs on social media. Visitors see high-quality web-optimized images without JPEG compression artifacts. The entire stack runs on free tiers with no ongoing hosting cost.

2. Tech Stack & Why

Next.js 16 (App Router)

Full-stack React framework. Gives us both the frontend and API routes in one project. Native Vercel integration means zero config deployment.

FrontendAPI

Tailwind CSS v4

Utility-first CSS. Configured via @import "tailwindcss" in globals.css (new Tailwind v4 syntax — no config file needed).

Styling

Prisma 7 + @prisma/adapter-pg

Type-safe ORM. Prisma 7 is a breaking change from v6 — it no longer accepts a url in schema.prisma and requires a database adapter at runtime.

ORM

Supabase (PostgreSQL)

Free hosted PostgreSQL. 500MB free tier, plenty for photo metadata. The direct connection URL is used for migrations; the pooler URL (port 6543) is used at runtime.

FreeDatabase

Cloudflare R2

Object storage for original photo files. 10GB free, no egress fees, no per-file size limit. Files are uploaded directly from the browser via presigned PUT URLs (bypasses Vercel's body size limit). Replaces Cloudinary which had a 10MB file cap.

FreeStorage

NextAuth v5 (Auth.js beta)

Authentication. Protects admin routes. Uses GitHub OAuth. v5 is a major API change from v4 — env var is AUTH_SECRET not NEXTAUTH_SECRET, and URL is AUTH_URL not NEXTAUTH_URL.

FreeAuth

Vercel

Hosting. Free hobby tier covers personal traffic easily. Automatic deploys from GitHub on every push. All pages are force-dynamic (server-rendered on demand).

FreeHosting

react-dropzone

Client-side drag-and-drop file upload UI. Files are uploaded directly from the browser to R2 via a presigned URL (bypassing Vercel's 4.5MB body size limit). Accepts JPEG, PNG, and WebP — RAW formats (DNG, CR2, etc.) are not supported for web display.

UI

5. How Key Features Work

Upload Flow

  1. Admin drops JPEG/PNG/WebP files on the dropzone in /admin/upload
  2. Browser calls POST /api/upload/sign — server generates an R2 presigned PUT URL (keeps credentials server-side)
  3. Browser uploads the file directly to Cloudflare R2 via the presigned URL with XHR (tracks progress, bypasses Vercel's body size limit)
  4. Browser reads the image dimensions client-side via a DOM img element
  5. Browser calls POST /api/upload/complete — saves photo metadata (storageKey, storageUrl, width, height) to Supabase

Important: Only upload JPEG/PNG/WebP. RAW formats like DNG cannot be displayed by browsers and cannot be properly decoded by Vercel's image optimizer. Export from Lightroom at quality 90–95, sRGB before uploading.

Image Delivery

Original files are stored in Cloudflare R2. All images are served through Vercel's Image Optimization API at quality={100}, which converts the source file to WebP and serves it via CDN.

  • Slideshow & detail page: quality={100} — Vercel fetches from R2 server-side, converts to WebP, caches on CDN
  • Grid cards: Default Next.js image optimization

Do not use unoptimized on image components — it bypasses Vercel and loads directly from R2, which fails for any non-JPEG format the browser can't natively render.

Delete Photo

DELETE /api/photos/[id] handles full cleanup in order:

  1. Clears any album that uses this photo as its cover (coverPhotoId → null)
  2. Clears SiteSettings if this photo is the hero (heroPhotoId → null)
  3. Deletes the database record
  4. Deletes the file from Cloudflare R2

Accessible from two places: the photo detail page (admin-only "Delete photo" button with two-step confirm) and the admin dashboard (click any thumbnail to show a confirm overlay).

Social Sharing (Open Graph)

Each photo detail page (/photos/[id]) exports generateMetadata() which sets og:image to a 1200×630 Cloudinary-cropped version of the photo. When you share the URL on social media, the platform fetches these tags and shows a rich preview.

Admin Auth Guard

app/admin/layout.tsx is a server component that calls auth() from NextAuth on every request. If there's no session, it redirects to /login. No client-side logic needed.

# Cloudflare R2
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET_NAME=         # e.g. photo-portfolio
R2_PUBLIC_URL=          # e.g. https://pub-HASH.r2.dev — must match next.config.ts remotePatterns

# NextAuth v5 — note: AUTH_* prefix, not NEXTAUTH_* (that was v4)
AUTH_SECRET=            # Random 32-byte base64 string
AUTH_GITHUB_ID=
AUTH_GITHUB_SECRET=
NEXTAUTH_URL=           # Full site URL — e.g. https://photo-portfolio-three-amber.vercel.app

7. Issues Encountered & How We Fixed Them

Node.js not in PowerShell PATH

node : The term 'node' is not recognized as the name of a cmdlet...

Node was installed at C:\Program Files\nodejs\ but the tool's PowerShell session didn't have it in PATH.

Fix: Prefix every Node/npm command with $env:PATH = "C:\Program Files\nodejs;" + $env:PATH. Also ran Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser to allow npm scripts.

Prisma 7 — url field removed from schema.prisma

Error: The datasource property `url` is no longer supported in schema files.

Prisma 7 removed the url = env("DATABASE_URL") line from schema.prisma. The URL is now configured in prisma.config.ts (for CLI/migrations) and passed via an adapter in the client constructor.

Fix: Removed url from schema.prisma. Installed @prisma/adapter-pg and pg. Updated lib/db.ts to use new PrismaPg({ connectionString: process.env.DATABASE_URL }) passed to new PrismaClient({ adapter }).

Prisma 7 — generated client path changed

Cannot find module '@/app/generated/prisma'

Prisma 7 generates the client to a custom output path (app/generated/prisma/) with no index.ts, so directory imports fail.

Fix: Import from the specific file: import { PrismaClient } from "@/app/generated/prisma/client"

Build failing — static pre-rendering hits the database

Error [PrismaClientKnownRequestError]: ECONNREFUSED — Export encountered an error on /albums

Next.js tries to statically pre-render pages at build time. Pages that call the database fail because there's no live DB connection during Vercel's build step.

Fix: Added export const dynamic = "force-dynamic" to every page that queries the database. This tells Next.js to always server-render these pages on demand instead of pre-rendering.

Supabase — can't reach database on port 5432

Error: P1001: Can't reach database server at db.upjmxwoaeckdziumiykh.supabase.co:5432

Port 5432 (direct Postgres) was blocked by the network. Also, the connection string from Supabase's UI has [YOUR-PASSWORD] as a placeholder — it never shows the real password.

Fix: Used Supabase's Connect button → copied the two connection strings (pooler + direct). Reset the database password in Supabase settings. Updated prisma.config.ts to use DIRECT_URL for migrations, and lib/db.ts to use the pooler DATABASE_URL at runtime.

Vercel build — Prisma client not found

Module not found: Can't resolve '@/app/generated/prisma/client'

The generated Prisma client (app/generated/prisma/) is in .gitignore so it's never pushed to GitHub. Vercel's build step starts with a fresh clone and never generates the client.

Fix: Added "postinstall": "prisma generate" to package.json scripts. Vercel runs npm install then automatically runs postinstall, generating the client before the build starts.

Cloudinary — file size too large / replaced with R2

File size too large. Got 49253646. Maximum is 10485760.

Cloudinary's free tier rejects files over 10MB. RAW camera files are 20–50MB.

Fix: Replaced Cloudinary entirely with Cloudflare R2. Upload flow changed to a presigned PUT URL (browser → R2 directly). No per-file size limit. Removed all Cloudinary dependencies and URL helpers. Updated next.config.ts to whitelist the R2 public hostname.

Images blurry/pixelated in gallery — DNG RAW format

After switching to R2, images in the gallery appeared blurry and pixelated. The root cause: photos were uploaded as .dng (RAW camera files). Browsers cannot render DNG natively. Vercel's Image Optimizer (Sharp) treats DNG as TIFF and reads partial data — either a low-res embedded thumbnail or raw Bayer pattern data — producing a blurry/pixelated result.

Fix: RAW formats are fundamentally not web-displayable. The correct workflow is to export from Lightroom/Photos as JPEG (quality 90–95, sRGB) before uploading. Updated the upload dropzone hint to make this clear. Deleted DNG files from R2 and re-uploaded as JPEG exports.

Photo detail page blank — unoptimized + non-JPEG format

The photo detail page (/photos/[id]) showed nothing — just the filename. The image component had unoptimized set, which bypasses Vercel's optimizer and loads the R2 URL directly in the browser. Browsers cannot render DNG files, so the image area was empty.

Fix: Changed unoptimized to quality={100} on the detail page. This routes through Vercel's Image Optimizer, which fetches from R2 server-side and converts to WebP before serving. Rule: never use unoptimized — always use the Vercel optimizer so format conversion is handled server-side.

NextAuth v5 — wrong environment variable names

TypeError: Invalid URL — input: 'AUTH_URL=https://photo-portfolio...'

Two issues: (1) NextAuth v5 uses AUTH_URL not NEXTAUTH_URL. (2) The value was accidentally entered as AUTH_URL=https://... (including the key name) instead of just the URL value.

Fix: In Vercel env vars, set Name = AUTH_URL and Value = https://photo-portfolio-three-amber.vercel.app (no prefix, no equals sign). Remove NEXTAUTH_URL from Vercel to avoid conflicts.

GitHub OAuth — wrong app credentials / callback mismatch

Be careful! The redirect_uri is not associated with this application.

Three separate OAuth apps were created over the session, and the credentials in Vercel didn't match the app that had the correct callback URL registered. GitHub OAuth Apps also had issues with the PKCE flow.

Fix: Created a new GitHub App (instead of OAuth App) called MyPhotoPortfolio. Set the callback URL to https://photo-portfolio-three-amber.vercel.app/api/auth/callback/github. Updated AUTH_GITHUB_ID and AUTH_GITHUB_SECRET in Vercel with the new app's credentials. Also created a custom /login page to replace NextAuth's built-in sign-in page.
